## Question

K(n, q) is the least size of a Kakeya set in F_q^n (a set containing a full line in every
direction). Over F_3, v1.1.0 of this repository proved K(3, 3) = 13 and found a 27-point Kakeya set
in F_3^4 (`data/kakeya-min-v1/results.json`), below the 31 points of the classical construction.
The best lower bound is 18 (Bukh-Chao). The solvers in `kakeya-min-v1` stopped at their time limits
with the lower bound still at 18. As far as we found (web search, 2026-11-20), no exact value
K(n, 3) with n >= 4 is known. **Is K(4, 3) = 27, or is there a Kakeya set of 26 points?**

## Reduction (fixed in advance)

Write F_3^4 = F_3^3 x F_3, points (y, s), slices K_s = {y : (y, s) in K}.

1. *Transversal directions.* A direction (w, 1), w in F_3^3 (27 of them), has a line in K iff some
   a in K_0 has a + w in K_1 and a + 2w in K_2.
2. *Horizontal directions.* A direction (w, 0), w in PG(2, 3) (13 of them), has a line in K iff
   some slice K_s contains a line of F_3^3 in direction w.
3. *Smallest section.* If |K| <= 26, some affine hyperplane H meets K in n <= 8 points (three
   parallel sections add up to |K|), and n >= 1 (a transversal line meets every parallel
   hyperplane). An affine map of F_3^4 sends H to {s = 0}; then (y, s) -> (A y + b, s), which is
   affine on F_3^4, sends K_0 to the canonical representative R of its orbit under AGL(3, 3)
   (303,264 elements). The image is a Kakeya set of the same size whose every hyperplane section
   has at least |R| points.
4. So K(4, 3) >= 27 follows if, for every orbit representative R of a k-subset of F_3^3 with
   1 <= k <= 8, the 0/1 model MODEL(R, 26) is infeasible: 54 point variables for K_1 and K_2,
   conditions 1 and 2, all 120 hyperplane sections >= |R|, and |K| <= 26.

The orbit representatives are generated by adding one point at a time and keeping the
lexicographically least image under all of AGL(3, 3). This is complete because every k-set contains a
(k-1)-set. Each model is solved by OR-Tools CP-SAT (900 s limit) and independently by HiGHS
(scipy.optimize.milp, 600 s limit). Every solution either solver returns is re-checked by a
brute-force Kakeya test that does not use the slice reduction.

## Self-checks (a failure = BUG)

- The group has 303,264 distinct permutations. For each k <= 9, the orbit sizes |G|/|Stab(R)| add
  up to C(27, k).
- The published 27-point set is Kakeya. After normalisation, both solvers accept it when its slices
  are fixed at bound 27 and reject the same fixed set at bound 26. The unfixed model for its
  representative is feasible at bound 27, and that solution passes the brute-force check.
- The classical 31-point set passes the slice test, and on 60 random perturbations the slice test
  agrees with the brute-force test (unit tests).
- At bound 27, CP-SAT finds at least one set (60 s per representative, k <= 9).
- No returned solution fails the brute-force check, and the solvers do not disagree on any case.

## Verdicts

- **K43-EQ-27**: every case INFEASIBLE in both CP-SAT and HiGHS. Then K(4, 3) = 27
  (computer-assisted, two independent MILP/CP solvers, as for K(3, 3) = 13). It would be the first
  exact Kakeya number over F_3 in dimension 4.
- **K43-EQ-27-CPSAT-ONLY**: every case INFEASIBLE in CP-SAT, with some HiGHS cases unknown. Then we
  report K(4, 3) = 27 as CP-SAT-only and file a -v2 with longer HiGHS limits or a third method.
- **K43-LE-26**: a verified Kakeya set of at most 26 points. Then K(4, 3) <= 26, a new upper bound.
  The set is published, and the next job asks for 25.
- **UNDECIDED**: some cases were decided by neither solver. We report the solved cases and the open
  representatives.
- **BUG**: any self-check fails. Then nothing is claimed; we fix the code and file -v2.

CP-SAT and HiGHS infeasibility claims are not independently checkable certificates, so any exact value
from this job is stated as "computer-assisted (two solvers)".
